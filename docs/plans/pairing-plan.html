Clocktower · rating design for the model timeline

Every model meets most others, and close neighbours meet often

Ten frontier models from September 2025 to September 2026 play a near round robin in side-swapped pairs, twelve-player tables. The fit gives each model one combined rating, split into detection (playing good) and deception (playing evil).

Who plays whom

Rows and columns are the models in release order. Each cell is the number of side-swapped pairs that matchup gets: 6 when the models are one or two releases apart, 4 when three to five apart, 2 when further. Close matchups get more games because near-even games carry the most information; distant ones still get some, so the top and bottom of the ranking are compared directly and the fit can check it is consistent.

Why this shape

In a Bradley–Terry fit, the uncertainty between two ratings behaves like electrical resistance between them in the graph of who played whom. A chain of neighbours is resistors in series: errors pile up from one end to the other. Many cross-links are resistors in parallel. How it runs

One command launches all 45 matchups at once, each a batch of its pairs with its own seeds. Nothing is staged. I check the run myself every ten minutes: spend against plan, lost or capped turns by model, and a few transcripts.

# the plan: models in release order, pairs per matchup by release gap
python -m clocktower tournament plans/t3.json --players 12 --out games/v8/t3

# what it launches for each matchup, e.g. Opus 4.8 against GPT-6 Astra (4 pairs)
python -m clocktower run --games 4 --swap --seed 61230 --players 12 \
    --good-model claude-opus-4-8 --evil-model gpt-6-astra --out games/v8/t3-opus48-vs-astra

# while it runs: a read-only status report
python -m clocktower status games/v8/t3

# afterwards: ratings with 95% intervals
python -m clocktower ratings games/v8/t3-*/game-*

The tournament, status and ratings commands are proposed; the run line works today.
