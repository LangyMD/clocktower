Why a full round robin

Rating precision depends on how well the graph of matchups connects the models, not on concentrating games anywhere. I compared designs at the same budget (480 games) in a Bradley–Terry simulation. Two columns: the smallest gap between release-order neighbours the fit reliably detects, and the 95% interval on one model's rating, both in Elo. Lower is better.

Chain of neighbours14620316

Every well-connected design lands within about 5% of the others; only the chain fails. That matches the literature: pairwise-comparison error is governed by the comparison graph's connectivity, and well-connected graphs are near-optimal (Shah et al., JMLR 2016). The full round robin is the one design with no arbitrary choices, so it's the one to freeze. What 420 games resolve is about one model generation (~350 Elo); separating release-order neighbours would take about 10× more games.

How it would run

# one batch per matchup, all 105 launched at once; the seed fixes the table size (10 + seed % 3)
python -m clocktower run --games 2 --swap --seed 80000 --players 10-12 \
    --good-model claude-opus-4-8 --evil-model gpt-6-astra --out games/v12/f1-opus48-v-astra

# ratings: detection and deception per model, one Bradley–Terry fit, plus probe scores
python -m clocktower analyze games/v12/f1-*/game-*
